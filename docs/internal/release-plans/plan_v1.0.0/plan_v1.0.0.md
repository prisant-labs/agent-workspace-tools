# Release Plan: v1.0.0

## Theme

The complete Windows-native awt CLI: mover + inventory + retention + associate.

## Context

v1.0.0 is defined per the maintainer's 2026-07-11 directive: v1 is everything the
CLI does; v2 is the GUI. That folds the design's old "v1.0 mover" (TDD plan phases
1-9) and "v1.1 features F13-F15" (phases 13-15) into this single release. Old
phases 10 (cross-volume move, AC-2) and 11 (Codex/Gemini adapters, AC-27) are
defined-in-CLI but deliberately deferred; they park as promotable backlog (see D2).
The Tauri GUI (old phase 12, AC-25) is v2.0.0.

Program context and workstreams (CI, documentation): `docs/ROADMAP.md`. Validated
design: `docs/DESIGN.md`. Executable plan: `docs/superpowers/plans/2026-07-10-claude-project-mover.md`
(audit-repaired 2026-07-11; see `docs/CHANGELOG.md`). The v0.1.0 doctor milestone
(read-only, phases 1-4, honesty checkpoint) is an internal gate inside this
release, optionally tagged (D4).

Efforts are created directly in this folder rather than promoted from
`_unassigned/` (see D3): S-01 (mover CLI, carved spec with AC-1, AC-3..24, AC-26)
and S-02 (pointer spec to the committed F13-F15 spec, AC-28..44).

### D2: Old phases 10-11 parked, not in v1.0.0 (Resolved)

**Summary.** Cross-volume move (AC-2) and Codex/Gemini adapters (AC-27) are
defined CLI functionality but were explicitly deferred by the approved design.

**Context.** The directive "v1 is everything we have defined in CLI" could read
either way. DESIGN.md Section 9 defers phases 10-12; the audit found no blocking
need to pull 10-11 forward; both sit behind stable seams (copy primitives, adapter
registry).

**Desired outcome.** Nothing silently disappears; promotion stays cheap.

**Options / approaches.**

* **Option A:** Include phases 10-11 in v1.0.0 - honors the literal directive,
  but ships unplanned work (no TDD tasks exist for them) and delays the release.
* **Option B:** Park as promotable v1.x backlog - honors the design's deferral;
  AC-2/AC-27 stay visible in S-01's Deferred AC section and in ROADMAP Section 1.

**Recommendation.** Option B.

---

> **Maintainer decision:** Option B applied; override by promoting future efforts
> (e.g. S-03 cross-volume, S-04 multi-CLI) into this or a later release.
>
> * **Status:** Resolved
> * **Choice:** Park phases 10-11 as v1.x backlog
> * **Reasoning:** v1.0.0 ships only work with an executable plan; deferral is
>   recorded, not silent.
> * **Decided by / date:** planning agent on design-of-record, 2026-07-11

### D3: Efforts created in-place; canonical docs not moved (Resolved)

**Summary.** The convention expects self-contained effort folders; awt's canonical
spec (F13-F15) and TDD plan are committed docs with existing cross-references.

**Context.** Moving `docs/features/v1.1-inventory-retention-reassociate.md` or the
TDD plan into effort folders would break links from DESIGN.md, CHANGELOG.md, and
the session log.

**Desired outcome.** The release folder self-describes without breaking the doc web.

**Options / approaches.**

* **Option A:** Move canonical docs into effort folders and fix all references.
* **Option B:** Effort folders hold real frontmattered specs where none existed
  (S-01, newly carved) and thin frontmattered pointers where a canonical doc
  already exists (S-02 spec; both implementation-plan.md files wrap the one
  canonical TDD plan).

**Recommendation.** Option B.

---

> **Maintainer decision:** Option B.
>
> * **Status:** Resolved
> * **Choice:** Wrappers/pointers; canonical docs stay put
> * **Reasoning:** Aggregation and gates read frontmatter, which wrappers carry;
>   link integrity is worth more than folder purity. Revisit at v2 if the doc web
>   is restructured.
> * **Decided by / date:** planning agent, 2026-07-11

### D5: One-time manual archive copy of ~/.claude/projects (Open)

**Summary.** A stopgap copy of live transcripts to a durable folder was offered in
the 2026-07-11 session log and never executed; F14 later automates this properly.

**Context.** `cleanupPeriodDays: 36500` is already set, so deletion pressure is
low, but a copy is the only real durability until F14 ships. Requires a
maintainer-chosen destination directory.

**Desired outcome.** Either an executed copy with a recorded destination, or an
explicit decision to wait for F14.

**Options / approaches.**

* **Option A:** Pick a destination now; run a one-time copy; record it here.
* **Option B:** Wait for F14 (`awt archive`), accepting the retention-setting
  safety net in the interim.

**Recommendation.** Option A if any transcripts are irreplaceable today; otherwise
B is defensible given the 36500-day setting.
