# Release Plan: v1.0.0

## Theme

The complete Windows-native awt CLI: mover + inventory + retention + associate + repair.

## Context

v1.0.0 is defined per the maintainer's 2026-07-11 directive: v1 is everything the
CLI does; v2 is the GUI. That folds the design's old "v1.0 mover" (TDD plan phases
1-9) and "v1.1 features F13-F15" (phases 13-15) into this single release. Old
phases 10 (cross-volume move, AC-2) and 11 (Codex/Gemini adapters, AC-27) are
defined-in-CLI but deliberately deferred; they park as promotable backlog (see D2).
The Tauri GUI (old phase 12, AC-25) is v2.0.0.

Program context and workstreams (CI, documentation): `docs/ROADMAP.md`. Validated
design: `docs/DESIGN.md`. Executable plan: `docs/superpowers/plans/2026-07-10-claude-project-mover.md`
(audit-repaired 2026-07-11; see `docs/CHANGELOG.md`). The v0.1.0 doctor milestone
(read-only, phases 1-4, honesty checkpoint) is an internal gate inside this
release, optionally tagged (D4).

Efforts are created directly in this folder rather than promoted from
`_unassigned/` (see D3): S-01 (mover CLI, carved spec with AC-1, AC-3..24, AC-26),
S-02 (pointer spec to the committed F13-F15 spec, AC-28..44), S-03 (drive-letter
repair, AC-45..AC-53a; folded in from a briefly-separate v1.1.0 plan, see D9), and
S-04 (safety closeout, AC-54..AC-65; opened 2026-07-30 after an adversarial audit
found data-loss paths the acceptance run does not exercise).

### D6: Repair drive-letter corruption in `history.jsonl`? (Open)

**Summary.** The live `history.jsonl` contains 45 distinct `project` values whose drive
letter has been replaced with a colon: `::\Projects\...` where `E:\Projects\...` belongs,
and `::\Backup - Data\:choesGPT\...` where `E:\Backup - Data\EchoesGPT\...` belongs. Every
capital `E` in the affected values became `:`.

**Context.** Found by the 2026-07-28 acceptance run and confirmed present in the live file
(the scratch copy is SHA-256 identical, so the copy did not introduce it). Origin unknown;
it predates awt. `awt doctor` correctly reports these as stale and correctly refuses to
guess at them, because guessing is exactly what the tool's design forbids.

**Desired outcome.** Either a deliberate repair capability, or a recorded decision that
these stay as they are.

**Options / approaches.**

* **Option A:** Leave them. They are inert: `history.jsonl` entries only affect prompt
  history recall for a path that no longer resolves. Nothing breaks.
* **Option B:** A v1.x `awt repair --drive-letter` that proposes `::\X` -> `<letter>:\X`
  where exactly one existing drive makes the path resolve, refusing when zero or more than
  one candidate matches. This fits the existing fail-closed posture.
* **Option C:** Fix by hand now with a one-off script.

**Recommendation.** Option A for v1.0 (out of scope, no harm), then Option B as a v1.x
candidate if the maintainer wants the history back. Option C is discouraged: a hand-rolled
sed over `history.jsonl` is precisely the unverified whole-file rewrite this project exists
to replace.

---

> **Maintainer decision:** option B, approved and shipped.
>
> * **Status:** Resolved
> * **Choice:** `awt repair --drive-letter` (S-03), one-candidate rule
> * **Reasoning:** Measured on the live file: 34 of 46 damaged values resolve on exactly one
>   drive and none on more than one, so the repair is deterministic; 2,303 of 3,121 damaged
>   lines recovered. Hand-editing was rejected as exactly the unverified whole-file rewrite
>   this project exists to replace.
> * **Decided by / date:** maintainer, 2026-07-30

### D7: What caused the corruption? (Open)

**Summary.** The transformation is systematic, not random: every capital `E` became `:`
(`E:\Projects` became `::\Projects`, and `EchoesGPT` became `:choesGPT` inside the same value).
A single-character substitution applied in one pass, confined to `history.jsonl` - zero `::`
values exist in `.claude.json` or in project directory names.

**Context.** It predates awt: nothing in this tool wrote the live `history.jsonl` before repair
shipped. The cause is upstream - Claude Code itself, an editor, a sync client, or a hand-run
script.

**Why it stays open.** Repair without a root cause risks being a treadmill. It shipped anyway
because 2,303 recoverable lines were worth recovering immediately, and the operation is safe,
narrow, and idempotent.

**The tripwire (the revisit condition, made precise).** The 12 unrepairable values (818 lines)
remain in the live file by design, and `awt doctor` reports every `::` value as stale. **If a
future `doctor` run reports more distinct `::` values than the 12 known leftovers, the cause is
live**: stop, diff the new values against the set recorded in the S-03 spec, and investigate
what wrote the file since the last clean run. Until that fires, no investigation is scheduled
and none is needed.

---

> **Maintainer decision:** documented as a tripwire, per the 2026-07-30 directive.
>
> * **Status:** Open (deliberately; closes when the tripwire fires and is chased, or never)
> * **Choice:** ship repair now; revisit only on evidence of recurrence
> * **Decided by / date:** maintainer, 2026-07-30

### D8: Should repair generalise beyond the drive prefix? (Resolved)

**Summary.** `repair` could have been a general fix-damaged-paths command.

**Outcome.** No. One named transformation per known corruption class, each with its own flag
and its own provable guard; `--drive-letter` repairs only when exactly one present drive
resolves the path. A repair command writes based on inference rather than a user-supplied path,
which makes it the most dangerous surface this tool could grow. Narrowness keeps each repair
auditable and bounds the blast radius of a wrong inference to one known shape.

---

> **Maintainer decision:** narrow by design.
>
> * **Status:** Resolved
> * **Choice:** one named transformation per corruption class
> * **Decided by / date:** maintainer approval of D6 option B, 2026-07-30
