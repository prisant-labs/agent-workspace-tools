# CPM Features F13-F15: Inventory, Retention, Re-associate/Export

Three features added 2026-07-10, planned on top of the v1 mover design
(`docs/DESIGN.md`). They share the same engine: the reverse index, the store
adapters, and the read/write split. Reference material:
`docs/reference/claude-data-model.md` (the data surface) and
`docs/reference/existing-solutions.md` (prior art).

Scope for all three: **Claude Code only in v1.1**, Codex/Gemini deferred behind the
same adapter boundary as the mover. Determinism and no-network constraints from
`DESIGN.md` apply unchanged.

Why these three now: the retention feature is time-sensitive. Measured on this
machine 2026-07-10, transcripts are being auto-deleted at the 30-day default; the
oldest of 2,647 transcripts is 30 days old. Every day without archival loses history.

**Implementation status (2026-07-21): all three shipped.** F13 (`cpm list`), F14
(`cpm archive`), and F15 (`cpm associate`) are implemented on `main`, test-backed, and each
passed an adversarial review with its findings fixed (including making `associate` merge into
an existing destination reversibly). Per-command usage is in `docs/reference/commands.md`; the
completion table is in the v1.0.0 release plan (S-02). Codex/Gemini adapters remain deferred to
v1.x behind the existing adapter boundary.

## F13 - Project inventory / report (`cpm list`)

### Purpose

Report every project Claude has state for, and the related files and declarations
for each - the plain "what exists" view that no existing tool provides (prior art is
all usage/cost lenses; see `existing-solutions.md` Section A).

### Behavior

`cpm list` builds the reverse index and, for each project, reports:

- the project path (from stored `cwd`) and its encoded dir;
- session count (number of `*.jsonl`), total transcript size, oldest/newest
  transcript age in days (so the 30-day cliff is visible);
- linked SESSION-keyed artifacts by sessionId: todos, file-history, session-env,
  tasks counts;
- PATH-keyed declarations: `~/.claude.json` `projects{}` key(s) and their variants,
  `githubRepoPaths` entries, `history.jsonl` line count, plugin state dirs;
- a health flag: `OK`, `STALE` (source folder gone), or `UNRESOLVED` (no recoverable
  cwd).

### Output forms (per user decision)

- default: a readable terminal table;
- `--json`: machine-readable, for scripting and the future GUI;
- `--html <path>`: a standalone browsable report (sortable table, per-project
  drill-down). Rendering may borrow from prior-art viewers rather than be built from
  scratch (see `existing-solutions.md` Section D). The HTML form foreshadows the GUI.

### Acceptance criteria

- **AC-28** - `cpm list` enumerates every project dir under `~/.claude/projects`,
  resolving each to its stored `cwd`, and flags dirs with no recoverable cwd as
  UNRESOLVED rather than omitting them.
- **AC-29** - For each project, the report includes session count, total transcript
  bytes, and oldest/newest transcript age in days.
- **AC-30** - The report links SESSION-keyed stores (todos, file-history,
  session-env, tasks) to each project by sessionId.
- **AC-31** - The report lists PATH-keyed declarations per project: claude.json
  key variants, githubRepoPaths entries, history.jsonl line count, plugin state dirs.
- **AC-32** - A project whose stored `cwd` folder no longer exists is flagged STALE.
- **AC-33** - `--json` and `--html <path>` produce the same underlying data as the
  terminal table (one model, three renderers); `--html` writes a self-contained file
  and nothing else is mutated.

### Notes

F13 needs only the read layer (mover phases 1-4). It is the natural extension of
`doctor`/`scan` and can ship with or immediately after the doctor milestone.

## F14 - Retention / archival (`cpm archive`)

### Purpose

Retain session logs far beyond the 30-day default - ideally indefinitely - by
copying them out to a durable, user-chosen location before Claude's startup cleanup
deletes them, and by keeping new sessions archived automatically. It is mostly text;
the intent is to keep all of it.

### The retention hazard (must be designed around)

From `claude-data-model.md` Section 5 and `existing-solutions.md` Section B:

- Cleanup runs on startup and deletes transcripts older than `cleanupPeriodDays`
  (default 30).
- `history.jsonl` never expires; transcripts do. Opposite lifetimes.
- **`cleanupPeriodDays: 0` is unsafe to rely on**: community reports (issue #23710)
  say it disables transcript *writing* rather than cleanup. Issue #62272 says cleanup
  keys off file mtime, so a high value still loses old untouched sessions.

Design consequence: the archive-out copy is the real durability mechanism. The
retention setting is only a safety net, and CPM sets a **large finite** value, never
0, with a printed warning about the discrepancy.

### Behavior

Three cooperating capabilities under `cpm archive`:

1. **Bulk archive (one-shot, incremental).** Copy every project's transcripts and
   its SESSION-keyed artifacts (file-history, session-env, tasks, todos) into the
   archive. Incremental and idempotent: dedup by **content SHA-256**, not mtime
   (dodging #62272). Re-running only copies what changed. A per-project
   `manifest.json` records sessionIds, hashes, and source paths.

2. **Auto-archive new sessions.** `cpm archive --install-hook` installs a
   `SessionEnd` hook (in `~/.claude/settings.json`) that invokes `cpm archive
   --session "$TRANSCRIPT_PATH"` when a session ends, so new history is captured as
   it completes, before any cleanup. `--uninstall-hook` reverts it.

3. **Safety-net retention.** `cpm archive --set-retention <days>` writes
   `cleanupPeriodDays` (default suggestion 3650) into `~/.claude/settings.json`,
   printing the #23710/#62272 warning and refusing `0` unless `--force-zero` is
   passed with an explicit acknowledgement.

### Archive location and form (per user decision)

- Location is a **user-defined folder** (`--archive-dir <path>`, or a persisted
  default). CPM is **git-agnostic**: it never runs git. The user decides whether that
  folder is a git repo, is `.gitignored`, is cloud-synced, or is a plain directory.
- Form: raw `*.jsonl` preserved **verbatim** (fully reversible) under a
  `projects/<enc>/` layout mirroring Claude, plus a generated `INDEX.md` (project ->
  sessions, dates, sizes). Optional `--render` also writes readable markdown per
  session (reuse a prior-art renderer).
- Atomic writes (temp file + rename). If the target resolves under a known
  cloud-sync root (OneDrive/Dropbox/Drive env vars), print a warning that sync
  clients can corrupt files mid-write - the same defense `repo-sync-tool` uses.

### Archive layout

```
<archive-dir>/
  projects/
    E--Projects-.../
      <sessionId>.jsonl          verbatim transcript
      <sessionId>/               tool-results, subagents (verbatim)
  session-artifacts/
    file-history/<sessionId>/    verbatim
    session-env/<sessionId>/
    tasks/<id>/
    todos/<sessionId>-*.json
  rendered/                      only with --render
    E--Projects-.../<sessionId>.md
  INDEX.md
  manifest.json                  per-run: hashes, counts, source paths
```

### Acceptance criteria

- **AC-34** - `cpm archive --archive-dir D` copies every project's transcripts to
  `D/projects/<enc>/` byte-for-byte; a re-run copies nothing unchanged (content-hash
  incremental).
- **AC-35** - The archive includes each session's SESSION-keyed artifacts
  (file-history, session-env, tasks, todos) under `D/session-artifacts/`.
- **AC-36** - `cpm archive --install-hook` adds a `SessionEnd` hook to
  `~/.claude/settings.json` that archives the ending session; `--uninstall-hook`
  removes exactly that hook and leaves other settings byte-identical.
- **AC-37** - `cpm archive --set-retention <n>` writes `cleanupPeriodDays: n`;
  passing `0` is refused unless `--force-zero`, and any value prints the #23710/#62272
  caveat.
- **AC-38** - Writes are atomic; if `--archive-dir` resolves under a cloud-sync root,
  a warning is printed. No network calls occur.
- **AC-39** - A `manifest.json` records, per archived session, its SHA-256, source
  path, and sizes, sufficient to detect drift and to verify a later restore.

### Notes

F14's copy engine reuses the mover's backup/snapshot primitives (mover phase 7). The
hook installer edits `settings.json` with the same parse-validate-splice discipline
as the mover's `claude.json` edits.

## F15 - Re-associate and export a project's sessions (`cpm associate`)

### Purpose

Support deprecating one folder while keeping its Claude history with another. Concrete
case: Folder A is being retired; kept files were manually moved to Folder B; before
deleting A, move A's Claude sessions so they belong to B and/or drop a portable,
backed-up copy into a subfolder of B. Works even though A's folder is already gone -
the sessions are found via stored `cwd`, not the (missing) folder.

### Behavior (per user decision: both capabilities, independently selectable)

`cpm associate --from A --to B` with two independent, composable modes:

- `--reassociate` (default on): rewrite Claude's PATH-keyed records so A's sessions
  resume under B. This is exactly the mover's state migration **without the folder
  move** (B already exists and holds the files). It runs the same plan/backup/apply/
  verify/rollback path over: projects dir rename, transcript `cwd`/path rewrite,
  claude.json key + githubRepoPaths, history.jsonl, plugin state dir.
- `--export` (default on): copy A's sessions and SESSION-keyed artifacts into a
  subfolder of B (`--export-subdir`, default `.claude-sessions/`) as a portable,
  self-describing backup with a manifest - the same archive format as F14.

Either mode can be disabled (`--no-reassociate`, `--no-export`) so the user gets
re-associate only, export only, or both.

### Difference from `cpm move`

`cpm move` relocates the folder and migrates state. `cpm associate` assumes the
folder is already handled by the user (moved or being deleted) and only touches
Claude's state, optionally exporting a copy into the destination. The source may not
exist on disk; the tool must not require it to.

### Acceptance criteria

- **AC-40** - `cpm associate --from A --to B` locates A's sessions via stored `cwd`
  even when A's folder no longer exists on disk.
- **AC-41** - With `--reassociate`, after apply, A's sessions resume under B: the
  encoded dir, transcript `cwd`, claude.json key, githubRepoPaths, history.jsonl, and
  plugin state dir all reference B; verify passes; the operation is backed up and
  rollback-able (reusing the mover's safety model).
- **AC-42** - With `--export`, A's transcripts and SESSION-keyed artifacts are copied
  into `B/<export-subdir>/` in the F14 archive format with a manifest.
- **AC-43** - `--no-reassociate` performs export only (Claude's live records
  untouched); `--no-export` performs re-association only (no copy placed in B). At
  least one mode must be active or the command errors.
- **AC-44** - If B already has a claude.json key (collision), the mover's
  `--on-collision` policy applies (refuse by default).

### Notes

F15 is almost entirely reuse: the mover engine minus `MoveTree`, plus the F14 archive
writer pointed at `B/<export-subdir>`. It depends on the full mover write path (mover
phases 5-9) and on F14's archive writer.

## Dependency and sequencing summary

| Feature | Reuses | Depends on |
|---------|--------|------------|
| F13 inventory | reverse index, adapters' detect, SESSION-keyed linkage | mover phases 1-4 |
| F14 archive | snapshot/copy primitives, settings.json edit discipline | mover phases 1-4, 7 |
| F15 associate | full mover write path minus MoveTree, F14 archive writer | mover phases 5-9, F14 |

F13 and F14 need only the read layer plus copy primitives, so they can land close to
the doctor milestone. F15 needs the complete mover, so it follows v1.0.
